## Learning objectives

## 1. What you are building

In the previous lesson, you designed a small database backend for eComMART. Now you will implement it in a working Python module.

The module will provide these operations:

| Function | Purpose |
|---|---|
| `get_all_products()` | Return all product records |

```sql
CREATE TABLE products (
    product_id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    category TEXT NOT NULL,
    price REAL NOT NULL,
    stock INTEGER NOT NULL
);
```

The `product_id` is generated by SQLite when an insert does not provide an ID. The application will use the same field names throughout the project.

## 4. Implement a function to list products

Add this function:

```python
def get_all_products():
    """Return all products ordered by product ID."""
    connection = sqlite3.connect(DATABASE_PATH)

    try:
        cursor = connection.execute(
            """
            SELECT product_id, name, category, price, stock
            FROM products
            ORDER BY product_id
            """
        )
        return cursor.fetchall()

    finally:
        connection.close()
```

### How it works

- The function opens a connection to the existing database.
- It runs a `SELECT` query to retrieve the five product fields.
- `fetchall()` returns the rows as a list of tuples.
- The `finally` block closes the connection even if the query fails.

The function returns data instead of printing it. That means a menu, report, or test can decide how to use the results.

## 5. Implement a function to find one product

Add:

```python
def get_product_by_id(product_id):
    """Return one product tuple, or None if the ID does not exist."""
    connection = sqlite3.connect(DATABASE_PATH)

    try:
        cursor = connection.execute(
            """
            SELECT product_id, name, category, price, stock
            FROM products
            WHERE product_id = ?
            """,
            (product_id,),
        )
        return cursor.fetchone()

    finally:
        connection.close()
```

The placeholder `?` keeps the product ID separate from the SQL statement. The parameter tuple contains one item, so it needs a trailing comma.

`fetchone()` returns a tuple when the record exists and `None` when no record matches. The caller must handle both possibilities.

## 6. Validate product input

Before adding or updating a product, check that the values are sensible for this beginner catalog.

Add this helper:

```python
def validate_product(name, category, price, stock):
    """Raise ValueError when a product's input is invalid."""
    if not isinstance(name, str) or not name.strip():
        raise ValueError("Product name must not be empty.")

    if not isinstance(category, str) or not category.strip():
        raise ValueError("Product category must not be empty.")

    if isinstance(price, bool) or not isinstance(price, (int, float)):
        raise ValueError("Price must be a number.")

    if price < 0:
        raise ValueError("Price cannot be negative.")

    if isinstance(stock, bool) or not isinstance(stock, int):
        raise ValueError("Stock must be a whole number.")

    if stock < 0:
        raise ValueError("Stock cannot be negative.")
```

This validation is intentionally simple. It rejects blank names and categories, negative prices, and invalid stock values. It also rejects `True` and `False` for price and stock because Python treats booleans as a kind of integer.

A production catalog would need more rules, but these checks are enough for the course project. User input collected with `input()` arrives as text, so a menu should convert the price and stock to the appropriate numeric types before calling the database functions.

## 7. Implement the add operation

Add:

```python
def add_product(name, category, price, stock):
    """Insert a product and return its new product ID."""
    validate_product(name, category, price, stock)

    connection = sqlite3.connect(DATABASE_PATH)

    try:
        cursor = connection.execute(
            """
            INSERT INTO products (name, category, price, stock)
            VALUES (?, ?, ?, ?)
            """,
            (name.strip(), category.strip(), float(price), stock),
        )

        new_product_id = cursor.lastrowid
        connection.commit()
        return new_product_id

    except sqlite3.Error:
        connection.rollback()
        raise

    finally:
        connection.close()
```

### Important details

- The `INSERT` statement omits `product_id`, so SQLite assigns the new ID.
- All four values use placeholders.
- The function strips leading and trailing whitespace from the name and category.
- `lastrowid` gives the ID assigned to the inserted row.
- The function commits after the insert succeeds.
- If SQLite raises an error, the function rolls back and re-raises the error so the caller can handle it.
- The connection closes in `finally`.

The function does not silently print success. It returns the new ID so the caller can decide what message to show.

### A note on `AUTOINCREMENT`

You may come across SQLite's `AUTOINCREMENT` keyword elsewhere and wonder why the `products` table does not use it:

```sql
product_id INTEGER PRIMARY KEY AUTOINCREMENT
```

Both `INTEGER PRIMARY KEY` on its own (what this course uses) and `INTEGER PRIMARY KEY AUTOINCREMENT` let SQLite assign the next ID automatically when an insert omits it. The difference only shows up after a deletion: plain `INTEGER PRIMARY KEY` may reuse an ID that was previously deleted, while `AUTOINCREMENT` guarantees an ID is never reused, even after its row is deleted.

For this course's catalog, that difference does not matter — product IDs are not referenced anywhere outside the `products` table, so a reused ID causes no harm. `AUTOINCREMENT` matters more in a design where other tables store a `product_id` as a foreign key (see the foreign-key illustration in `01_Database_Fundamentals/02_Tables_Records_and_Primary_Keys.md`), since a reused ID could then end up pointing at the wrong, newer product. Plain `INTEGER PRIMARY KEY` is the simpler and slightly faster choice when that risk does not apply, which is why it is used here.

## 8. Implement the update operation

Add:

```python
def update_product(product_id, name, category, price, stock):
    """Update a product; return True if a matching row was affected."""
    validate_product(name, category, price, stock)

    connection = sqlite3.connect(DATABASE_PATH)

    try:
        cursor = connection.execute(
            """
            UPDATE products
            SET name = ?,
                category = ?,
                price = ?,
                stock = ?
            WHERE product_id = ?
            """,
            (name.strip(), category.strip(), float(price), stock, product_id),
        )

        if cursor.rowcount != 1:
            connection.rollback()
            return False

        connection.commit()
        return True

    except sqlite3.Error:
        connection.rollback()
        raise

    finally:
        connection.close()
```

The `WHERE product_id = ?` condition limits the update to the requested product. Without that condition, the update could affect every row.

The function returns `True` when one matching row was affected. If no record matches, it rolls back and returns `False`. A database error is re-raised after rollback so the calling code can handle it.

## 9. Implement the delete operation

Add:

```python
def delete_product(product_id):
    """Delete one product; return True if a row was deleted."""
    connection = sqlite3.connect(DATABASE_PATH)

    try:
        cursor = connection.execute(
            "DELETE FROM products WHERE product_id = ?",
            (product_id,),
        )

        if cursor.rowcount != 1:
            connection.rollback()
            return False

        connection.commit()
        return True

    except sqlite3.Error:
        connection.rollback()
        raise

    finally:
        connection.close()
```

This function deletes only the record with the specified ID. It returns `False` if no row matches. Always confirm which product an ID refers to before deleting it.

import sqlite3

    if not isinstance(name, str) or not name.strip():
        raise ValueError("Product name must not be empty.")

    if not isinstance(category, str) or not category.strip():
        raise ValueError("Product category must not be empty.")

        raise ValueError("Price must be a number.")

    if price < 0:
        raise ValueError("Price cannot be negative.")

    if isinstance(stock, bool) or not isinstance(stock, int):
        raise ValueError("Stock must be a whole number.")

    if stock < 0:
        raise ValueError("Stock cannot be negative.")


def get_all_products():
    """Return all products ordered by product ID."""
    connection = sqlite3.connect(DATABASE_PATH)
    try:
        cursor = connection.execute(
            """
            SELECT product_id, name, category, price, stock
            FROM products
            ORDER BY product_id
            """

        return cursor.fetchall()
    finally:
        connection.close()


def get_product_by_id(product_id):
    """Return one product tuple, or None if the ID does not exist."""
    connection = sqlite3.connect(DATABASE_PATH)

            """

            FROM products
            WHERE product_id = ?
            """,
            (product_id,),
        )
        return cursor.fetchone()
    finally:
        connection.close()


def add_product(name, category, price, stock):
    """Insert a product and return its new product ID."""
    validate_product(name, category, price, stock)
    connection = sqlite3.connect(DATABASE_PATH)
    try:
        cursor = connection.execute(
            """
            INSERT INTO products (name, category, price, stock)
            VALUES (?, ?, ?, ?)
            """,
            (name.strip(), category.strip(), float(price), stock),
        )
        new_product_id = cursor.lastrowid
        connection.commit()
        return new_product_id
    except sqlite3.Error:
        connection.rollback()
        raise
    finally:
        connection.close()


def update_product(product_id, name, category, price, stock):
    """Update a product; return True if a matching row was affected."""
    validate_product(name, category, price, stock)
    connection = sqlite3.connect(DATABASE_PATH)
    try:
        cursor = connection.execute(
            """
            UPDATE products
            SET name = ?, category = ?, price = ?, stock = ?
            WHERE product_id = ?
            """,
            (name.strip(), category.strip(), float(price), stock, product_id),
        )
        if cursor.rowcount != 1:
            connection.rollback()
            return False
        connection.commit()
        return True
    except sqlite3.Error:
        connection.rollback()
        raise
    finally:
        connection.close()


def delete_product(product_id):
    """Delete one product; return True if a row was deleted."""
    connection = sqlite3.connect(DATABASE_PATH)
    try:
        cursor = connection.execute(
            "DELETE FROM products WHERE product_id = ?",
            (product_id,),
        )
        if cursor.rowcount != 1:
            connection.rollback()
            return False
        connection.commit()
        return True
    except sqlite3.Error:
        connection.rollback()
        raise
    finally:
        connection.close()

## 12. Common mistakes and fixes

| Mistake | Why it matters | Better approach |
|---|---|---|
| Using inconsistent column names | Queries may fail or return unexpected values | Use `product_id`, `name`, `category`, `price`, and `stock` consistently |
| Forgetting `WHERE` in update or delete | More rows than intended may be affected | Always target the product ID |
| Concatenating values into SQL | Can cause SQL injection and quoting problems | Use parameterized queries |
| Not checking for a missing product | The application may claim an update succeeded when no row matched | Check `rowcount` or the returned result |
| Forgetting to commit a change | The change may not be saved | Commit after a successful operation |
| Forgetting to close connections | Database resources may remain open | Use `finally` to close each connection |
| Returning printed text instead of data | Other parts of the program cannot easily reuse the result | Return records, IDs, or success statuses |
| Testing with a real catalog product | Can damage the starter data | Use a disposable practice record |
